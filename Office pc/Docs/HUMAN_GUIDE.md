# HUMAN_GUIDE.md

## Purpose

This project is a single-company Wal Mart Summary FastAPI workflow.
The goal is to keep the app stable, readable, and focused on the current Wal Mart Summary runtime.

## Moving to another PC

For a complete, human-readable and Codex AI-readable transfer guide, use
`Docs/Moveprojectdocs.md`. It explains the difference between the
clean runtime bundle and a full development-workspace move, target-PC setup,
configuration, validation, rollback, security, and mandatory AI maintenance rules.

Every XLSX workbook generated by Wall Mart Summary, Amazon Accounts, or Regular Accounts
stores `AnsSys & openpyxl` as its Creator and Last Modified By metadata.

Generated source-data sheets use normal Excel Tables. Users can select any included table
in Excel and use Insert → PivotTable for their own calculations. `Date` and `Due Date`
cells display as `MMDDYYYY` in generated data sheets. Regular Accounts top year totals are
formulas linked to `AGEING SHEET`; its interactive ageing summary values come from native
Excel PivotTables sourced from that sheet.

For Regular Accounts, the app also uses Microsoft Excel installed on the app-host PC to
silently add a real `DB'S BY REASON PIVOT` worksheet before download. It is not visible
on screen. The PivotTable uses `Order#` in Rows, `Ref Type=DB` as its filter, and sums
Total, Current, 1-30 Days, 31-60 Days, 61-90 Days, and Over 90 Days.

## Python Report Engine Template

The reusable Python-only report migration template is available at `Documention Both/DEEP FLOW DIAGRAM/PYTHON_REPORT_ENGINE_TEMPLATE.md`. It sets the common upload → validation → DataFrame calculation → formatted Excel download design used by Amazon and Regular Accounts, and the safe comparison-first path for moving Wal Mart Summary reports from SQL calculations to Python calculations.

The top yearly blocks and ageing titles in `INV SUMMARY` and `DB'S SUMMARY` remain unchanged.
Each summary's interactive PivotTable begins at column A below its title: `Ref Type` is the
filter row directly under the title, followed by one spacer row and then the Acct/amount
headers. INV uses `Ref Type=IN`, while DB uses `Ref Type=DB`. Values appear as Current,
1-30 Days, 31-60 Days, 61-90 Days, Over 90 Days, then Total.

This PivotTable work is a separate hidden pre-download step for every Regular Accounts
person report: the XLSX is saved, Excel updates the PivotTables, saves and closes, then the
browser download begins. Wall Mart Summary and Amazon are unchanged.

Duplicate filenames no longer block Steps 01, 02, or 03. Upload the same file again whenever you need to reprocess it. The app displays a top-right `Duplicate upload detected` notification and continues processing; the normal Step 01 replacement and Step 02 refresh behavior remain unchanged.

## Wal Mart Python Report

1. Choose `Wall Mart Summary` in Marketplace.
2. Upload a CSV, XLSX, or XLS inquiry file and click `Process Wal Mart File`.
3. Python validates the required columns, creates or refreshes `Ref Type` from `Ref#`, refreshes `total` from the five ageing columns, and immediately downloads `Wal Mart Status Summary YYYY-MM-DD HH-MM-SS.xlsx`.
4. The workbook retains the approved Wal Mart report template. No SQL Server table, query, or stored procedure is used.
5. In every Wal Mart output data sheet, Total and all five ageing amount columns display with a `$` currency symbol.
6. Excel serial values in Date or Due Date, such as `44548`, are converted to normal `MM/DD/YYYY` dates.
7. A row with a blank Comment keeps all comment-based helper values, including `PaidStatus`, blank in every Wal Mart output data sheet; InvYear still comes from Date.
8. `PaidStatus` is never set to a generic Paid value; only explicit Unpaid and InvPaid rules populate it.

The automatic workbook exports these tables in order when they contain rows: `DBs_Status`, `Invoices_Status`, `SA9200_DBs`, `SA9200_Invoices`, `WA9085_DBs`, `WA9085_Invoices`, `WallMartSummary_Sheet`, `WC9085_DBs`, `WC9085_Invoices`, and `WM9263_Invoices`. Empty tables are skipped. `Invoices_Status` and `DBs_Status` keep their formatted summary layouts and use every four-digit year column supplied by the current SQL data; the formatted invoice-status sheet hides any account whose report values are all null, zero, or negative, while the formatted DB-status sheet hides an account section when it has no detail rows or no `ACCOUNT TOTAL` row. The DB-status layout shows `Dispute_Amount` between `Total Amount` and `Write-up Sent`, formatted as currency. The `RetailLinkStatus` SQL field is shown under the final Excel header `No Record Found`. All individual workflow buttons remain available and keep their existing manual behavior.

## Company Processing Selection

Use the Marketplace selector before uploading. `Wal Mart Summary` is file-only: its Python processor validates the required Wal Mart columns, preserves all original/extra columns in `WallMartSummary_Sheet`, refreshes `total` from Current through Over 90 Days, and uses `ref` contains matching to classify IN, DB, and CR rows. It copies the approved Wal Mart template for the report, then downloads the finished workbook without opening a database connection. `Amazon Accounts` is file-only: uploading an Amazon status file normalizes it and saves the workbook in `output/amazonaccounts/` without opening a database connection. `Regular Accounts` is serverless: choosing an `.xlsx` workbook reads its `Full Ageing` sheet locally, finds the row with `Assigned Person` and `Acct` headers, then fills the Person Name dropdown as `{Person Name} @{count(unique Acct values)}`. After selecting a person, click Process to download `{Person Name} {Uploaded File Name}.xlsx`. The report contains all selected-person rows in `AGEING SHEET`, nonblank-Status rows in `FOLLOW-UP ENTRIES`, a `Past-due invoices` sheet (right after FOLLOW-UP ENTRIES) with every AGEING SHEET row whose Due Date is on or before the next Monday counted from the browser's today (when today is Monday, today is used) - a `Due Status` column next to Due Date (Overdue / Due today / Due soon) recalculates from `TODAY()` each time the file opens, and the yellow box on the right of that sheet holds the Today and Next Monday formulas it reads - IN/DB ageing summaries, and one sheet for each unique Acct. Its data sheets preserve every source column, original header wording/order, and source value, including `Status`. It does not use SQL Server. Wal Mart stored procedures are not run for any file-only option.

For Amazon, the processor reads every source worksheet and uses `Acct` plus `Ref Type` instead of trusting worksheet names. `IN` rows go to `<Acct>_Invoices`, `DB` rows to `<Acct>_DBs`, and `CR` rows to `<Acct>_CRs`. It creates an account/type sheet only when it has source rows.

The first three sheets are status sheets in this exact order: `DB's Status`, `Invoice's Status`, and `CR's Status`. DB and Invoice are populated from the Amazon upload; CR remains ready for its future rule.

`Master Aging` is sheet four. It contains every nonblank data row from every uploaded sheet, without limiting the data to AM9285, AM9286, ME9145, IN, DB, or CR.

Their visual formatting is ready now: `DB's Status` uses the DB status template, while `Invoice's Status` and `CR's Status` use the invoice status template. The workbook copies no Wal Mart data into these Amazon sheets.

After `Process Amazon File` completes, the browser automatically downloads the workbook. Its filename is `Amazon Status Summary YYYY-MM-DD HH-MM-SS.xlsx`; the date and time are generated at the moment of the download.

The Amazon process button uses the browser's normal download response. It remains `Processing...` until the server has finished sending that download, then returns to normal. It does not use a fixed timeout.

`DB's Status` is now populated from the uploaded Amazon data. Only rows with `Ref Type=DB` are used. For each account, the sheet creates one row per distinct `Order#`, generates its year columns from distinct valid `Date` years, and places the summed `Total` at each Order#/year intersection. `Write-up Sent` sums `Total` only where `Comment` contains `MEMO`, case-insensitively. `Dispute_Amount` is not included in the Amazon DB status sheet.

`Invoice's Status` uses only `Ref Type=IN` rows. It creates dynamic year columns from valid `Date` years, sums `Total` by `Acct` and year, and creates each account's `Total Amount`. Its last column is named `Paid @<latest year>` and uses that latest Date year only. It groups matching rows by `Acct`, `Comment`, and year, then sums `Total` when Comment contains `Paid on`, a payment-number phrase, and digits. Small spelling errors such as `payemnt no` are accepted, without changing the Total Amount calculation.

`CR's Status` uses only verified `Ref Type=CR` rows, which are the same source rows written to each `<Acct>_CRs` sheet. It creates dynamic year columns from Date, sums `Total` by account and year, and includes `Total Amount`. Its Status column is intentionally a `-` placeholder.

Universal Amazon status rule: do not show an account section when its final `Total Amount` is `0.00`. This applies regardless of account position, so an empty first, second, or third account is omitted from the summary.

Amazon account/type workbook rule: create `<Acct>_Invoices`, `<Acct>_DBs`, or `<Acct>_CRs` only when that account/type has at least one source row. Empty account/type sheets are omitted.

After the final visible Amazon status account section, all unused rows and their copied template formatting are removed. Empty accounts leave no title, table, spacer, or formatting footprint.

All sections below the Full Report area are collapsed under `Expand Workflow Tools`, including runtime details, manual procedures, workbook tools, table preview, and configuration/health links.

## Progress Panel

While Regular Accounts, Wal Mart Summary, or Amazon Accounts is processing, a progress bar appears under the Process button. It shows the percentage, the file being processed, the current step, elapsed seconds, and a Stop & refresh button.

- Regular Accounts reports show exact steps: reading the Full Ageing sheet, preparing summaries, saving the workbook, building PivotTables in Excel (the longest step), then the download.
- The Regular Accounts report downloads without leaving the page. If it fails, the panel stays red with the reason instead of replacing the page with an error.
- The Full Ageing sheet is cached in `app/local.db` after the first read, so choosing a person and building the report read the workbook once.
- A person with fewer than 2 rows of an IN, CR, or DB type gets no PivotTable for that type; a NOTICE sheet in the workbook lists what was skipped.

## New Ageing

New Ageing runs entirely in the browser (ExcelJS); the workbooks are not uploaded to the server.

1. Choose **New Ageing** as the marketplace.
2. Click or drop the **OLD** workbook, then the **NEW** workbook (both `.xlsx`).
3. Leave Sheet as `Full Ageing` and the key column as `Ref#` unless your workbook differs, then click **Find new entries**.
4. The page shows Old entries, New file entries, New entries, and Gone (in old, not in new), plus a filterable preview.
5. Use the **Person** dropdown (built from the Assigned Person column of the new entries, with row counts) to preview and download only one person's rows. The match is exact, including capitals.
6. **Download new entries (.xlsx)** keeps the original columns, widths and formatting of the NEW file. **Download gone entries (.xlsx)** does the same for rows that disappeared. The green notice names the downloaded file.

The Process buttons on the Wal Mart Summary and Amazon Accounts pages stay disabled until a file is chosen.

Matching is by Ref# only (trimmed, case-insensitive). Tick "Remove rows above header in download" to drop title rows above the header row.
