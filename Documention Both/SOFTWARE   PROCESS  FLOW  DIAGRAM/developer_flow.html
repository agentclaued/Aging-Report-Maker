Overstock Developer Flow

Process name: Overstock Data Processing Workflow

This diagram shows the technical request lifecycle across FastAPI routes, file staging, pandas processing, SQL execution, duplicate management, logging, and error handling.

flowchart TD A([Start]) --> B[Frontend renders Overstock-only dashboard] B --> C[User selects step and submits form] C --> D{Route type} D -->|Step 01 upload| E[POST /process/step-01] D -->|SQL / summary action| H[POST to step-specific process endpoint] E --> J[FastAPI validates request and selected company code] H --> J J --> K[build_services loads Overstock profile and runtime config] K --> L[Repository ensures SQL Server database is available] L --> M{Request category} M -->|Step 01| N[Save upload to temp storage] N --> O[InquiryProcessor reads file into pandas DataFrame] O --> P[Normalize SQL-safe column names] P --> Q[Apply company aliases and required-column validation] Q --> R[Prepare derived columns like Ndatee, pay_day, and Cclaim] R --> S[Write STEP_01_NORMALIZED_INQUIRY.xlsx] S --> T[Upload normalized rows into step_01_inquiry_rows] T --> U[Run SQL script to create CR, IN, and DB split tables] U --> V[Log status and append history event] M -->|SQL / summary action| AR[Execute step-specific SQL script through repository] AR --> AS[Read target table counts or execution messages] AS --> AT[Log status and append history event] V --> AZ[Render HTML response with success or failure message] AT --> AZ AZ --> BA{Exception raised anywhere?} BA -->|No| BB([End]) BA -->|Yes| BC[Catch exception, log error, append history, return error response] BC --> BB
